# The headline result, and the hypotheses it suggests

This note explains the single strongest result in the project so far, why it
is surprising, which part of it we can already prove, and which testable
hypotheses fall out of the unexplained part. Numbers are from the current
paper-scale pilot runs (tag `paper-scale-pilot`), regenerated by
`benchmarks/deeponet/study.jl` and `benchmarks/field/study.jl`.

## The result

Training through hard output correction improves accuracy and enforces the
constraints exactly, at the same time.

On the DeepONet-style heat operator (20 seeds, synthetic scope):

| variant | RMSE | max boundary violation | max mass violation |
| --- | --- | --- | --- |
| vanilla | 0.0602 | 0.1972 | 0.0582 |
| best swept soft penalty | 0.0609 | 0.1708 | 0.0677 |
| evaluation-only correction | 0.0431 | 0 | 3e-16 |
| train-time hard correction | 0.0245 | 0 | 6e-16 |

On the fixed-grid field benchmark (10 seeds): projected RMSE 0.0112 against
vanilla 0.0267 with mass error at numerical precision, while the soft sweep
degrades accuracy as beta grows without ever enforcing mass.

Every projection across both studies returned `:success`, so no claim rests
on an invalid gradient.

## Why this is surprising

The naive expectation is a tradeoff. Projection restricts the output, so
forcing exact feasibility should cost accuracy, the way hard constraints
usually cost objective value in optimization. Instead, feasibility is better
than free here: the hard-corrected model is about 2.5 times more accurate
than vanilla, and the swept soft penalty, the standard tool, never reaches
exact feasibility and never beats vanilla accuracy.

## The half we can already prove

The evaluation-only improvement is not a mystery. The constraint sets are
convex, and in these benchmarks the targets are exactly feasible. Euclidean
projection onto a convex set is non-expansive, and a feasible target is a
fixed point of the projection, so for every sample

```
|| P(yhat) - y || <= || yhat - y ||    whenever y is in C.
```

Projection of the prediction can only move it closer to a feasible target.
Evaluation-only correction therefore can never hurt RMSE under these
conditions, and the observed drop from 0.0602 to 0.0431 is this theorem at
work. This argument belongs in the paper as a lemma.

## The half we cannot yet explain

The interesting gap is between evaluation-only (0.0431) and train-time
correction (0.0245). The lemma explains none of that. Training through the
projection changes what the model learns, not just what it outputs, and the
size of the gain is the open scientific question.

## Hypotheses

- **H1, effective dimensionality reduction.** The projection maps every
  output onto an affine subspace (plus inactive bounds). Gradients through
  the projector are killed along constraint-normal directions, so the model
  only ever learns the feasible-subspace component of the target. The
  learning problem is effectively (K - m)-dimensional rather than
  K-dimensional, where m is the number of independent equality rows, and
  smaller hypothesis spaces learn faster from the same data.
- **H2, gradient conditioning.** The projected gradient removes
  constraint-normal error components that otherwise act as noise shared
  across samples (every sample fights the same boundary and mass error
  directions). Removing them could reduce gradient interference and speed
  optimization, independent of any capacity argument.
- **H3, soft penalties actively waste capacity.** Soft-plus-hard (0.0435) is
  notably worse than hard alone (0.0245). The penalty term pushes the raw
  output toward feasibility, which the projection already guarantees, and
  that pull competes with fitting the tangent component. This would explain
  why adding the penalty on top of the projection hurts.
- **H4, free drift is harmless here but load-bearing.** The raw output can
  drift along constrained directions with no gradient pushback (the heat
  study measured a mean correction norm of 10.1 behind all-success
  statuses). If the drift ever interacts with the active set, for example by
  pushing components across a bound, the picture should change.

## Predictions worth testing

1. **Per-sample non-expansiveness check.** From H0/the lemma: with feasible
   targets, evaluation-only correction reduces error on every individual
   sample, not just on average. Cheap, the artifacts to compute this already
   exist. Any violating sample would falsify the feasibility assumption, not
   the lemma.
2. **The gain should grow with constraint count.** From H1: adding more
   independent equality rows (for example interior collocation values) should
   widen the train-time gap roughly with m/K. A sweep over m at fixed K and
   data budget is a one-script experiment on the existing helper.
3. **A null-space oracle should match hard training.** From H1: a model that
   parameterizes only the feasible subspace directly (z = z_p + N q with N a
   null-space basis) removes the projection entirely. If it matches
   hard-corrected accuracy, the mechanism is dimensionality. If hard
   correction still wins, H2 has content beyond H1.
4. **Infeasible targets should shrink or reverse the gain.** The lemma needs
   exactly feasible targets. Adding label noise that breaks feasibility (or
   using constraint values that disagree with the data, the realistic
   deployment case) should degrade evaluation-only correction first and
   train-time correction second. The crossover point matters for the summer
   geothermal data, where discrete balances will not hold exactly.
5. **The gain should be largest in the low-data regime.** From H1: shrink
   train_samples and the relative advantage of hard correction over vanilla
   should grow. Directly testable with the existing scenario overrides.
6. **Bound the drift, watch the accuracy.** From H3 and H4: a very small raw
   anchor (tiny beta) should cap the correction norm. H3 predicts even a tiny
   anchor costs tangent accuracy. H4 predicts a regime where capping drift is
   free. The soft-sweep machinery already supports this at small beta values.

## First experimental returns (2026-06-12)

`benchmarks/deeponet/mechanism_study.jl` ran predictions 1, 5, and 4 at 5
seeds. Artifacts: `mechanism_nonexpansive.csv`, `mechanism_low_data.csv`,
`mechanism_noise.csv`, `mechanism_summary.csv`, `mechanism_statuses.csv`.

**Prediction 1 verified.** Across 80 held-out samples, evaluation-only
correction reduced the error of every single sample. The largest delta was
strictly negative (-1.14e-2) and target infeasibility was exactly zero. The
lemma is now empirically checked, and a permanent testset
(`projection non-expansiveness on feasible targets`) guards it.

**Prediction 5 refuted.** The naive low-data version of H1 predicted the
hard-correction advantage grows as training data shrinks. The opposite
happened: the vanilla-to-hard RMSE ratio is 1.63 at 4 training samples,
2.18 at 8, 2.60 at 16, and saturates near 2.76 at 64. Reading: the
projection only removes the constraint-normal error component, and with
almost no data the tangent component is equally bad for everyone, so there
is little advantage to amplify. The dimensionality story needs revision:
the gain looks multiplicative on a model that has already learned
something, not a substitute for data.

**Prediction 4 confirmed and quantified.** With constraint values perturbed
away from the data, correction degrades smoothly and crosses below vanilla
(RMSE 0.0635) at a measurable noise scale:

| eps | eval-only RMSE | hard RMSE |
| --- | --- | --- |
| 0.00 | 0.0460 | 0.0254 |
| 0.02 | 0.0512 | 0.0333 |
| 0.05 | 0.0676 | 0.0548 |
| 0.10 | 0.0983 | 0.0884 |
| 0.20 | 0.1802 | 0.1743 |

Evaluation-only correction stops paying at eps = 0.05 and train-time
correction at eps = 0.10, where eps is the absolute noise scale on
constraint values against fields of order one. Train-time correction beats
evaluation-only at every noise level. The corrected output's violation of
the true boundary values tracks eps almost exactly, because the projection
faithfully enforces the wrong numbers. The practical rule for the summer
integration: constraint metadata must be accurate to a few percent of the
field scale, otherwise hard correction actively hurts, and the audit step
that checks metadata against data is not optional.

## What this result does not claim

- The constraint metadata in these benchmarks (mass, boundary values) is
  computed from the target itself, so targets are exactly feasible by
  construction and the constraints carry true information about the label.
  Real exported data gets no such guarantee, which is exactly what
  prediction 4 probes.
- Everything is synthetic, 1D, and small (K up to 96 in these tables). No
  geothermal or summer claim follows from any of it.
- Hard correction does not always improve accuracy. The pendulum
  short-horizon RMSE is our own counterexample, where the strongest soft
  penalty wins while hard correction wins feasibility and the long horizon.
